# Design

## 朝向的数据流

- `LocationService.toLocationFix` 读取 `Position.heading`，放进 `LocationFix.headingDeg`。这是内存字段：不进 `TrackPoint`、不进数据库、不进 GPX（见 ADR-0002）。
- 可信判定放在 `RecordingSession`，与速度死区同层，避免界面自己再算一遍：`ingestFix` 里按「≥ 1.0 m/s 采用 / < 0.5 m/s 冻结 / 之间保持」维护 `_currentHeadingDeg`。
- 首个朝向：最近两个落盘点算方位角；没有两点时用 `null`，界面就只画圆点而不是箭头。
- `RecordState` 暴露 `headingDeg` 与 `startPoint`；`LiveRouteMap` 只负责画，不做判定。

## 起点判定

- 会话里记录 `_startPoint`：第一个 `accuracyM == null || accuracyM <= 30` 的落盘点。
- 兜底：开始 30 秒后若仍未达标，取第一个带坐标的点当起点，避免隧道/楼群起步永远没有起点。
- 不能用 `liveTrack.first` 代替：实时轨迹首点同样会先收到不达标定位，而起点一旦落位就不该再变。
- 坐标转换沿用 `_toMap` 的单一口径，和轨迹、断口完全一致。

## 箭头与最短弧

- `AnimatedRotation` 的 `turns` 不能直接用 `heading / 360`：359° → 1° 会倒转一整圈。
- 做法：在状态里维护一个连续展开的角度 `_unwrappedDeg += shortestArcDelta(prev, next)`，`turns = _unwrappedDeg / 360`，动画 200 ms。角度计算放进纯函数，单独单测。
- 形状 22 dp 实心三角，深墨填充 + 1.5 dp 纸色描边，与 `kRouteCasing` 同源；不用主题色，否则和脚下那截同色轨迹融成一片。

## 标记组件

| 标记 | 尺寸 | 画法 | 出现范围 |
| --- | --- | --- | --- |
| 粗略定位 | 12 dp | 半透明墨色圆点 | 只有 `previewFix` 时 |
| 起点（记录页） | 18 dp | 主题色空心环，无字 | 起点落位后 |
| 起点（详情页） | 18 dp | 主题色空心环 +「起」 | 轨迹有坐标 |
| 终点（详情页） | 22 dp | 主题色实心旗标 +「终」 | 轨迹有坐标 |
| 断口端点 | 10 dp | 警告色空心环，不填充 | 有断口时 |

## 详情页取点

`RouteMap` 从 `segments` 的首段首点与末段末点取起终点，不再单独传参数：断口会把一条轨迹切成多段，直接取 `segments.first` / `segments.last` 才和画出来的线一致。

## 风险

- 安卓静止时常上报 `heading = 0`，而 0° 恰好是正北：速度门槛能挡掉绝大部分，先按此实现；真机若出现「运动时箭头朝北」，再加与轨迹方位角的交叉校验（偏差 > 60° 丢弃本次值）。
- `_compactLiveTrack` 折半压缩会保留索引 0，起点不受影响。
- 小屏 120 dp 地图带内同时有起点环、箭头、指北与比例尺，起点环不带字就是为了不挤。

## 测试

- 纯函数：最短弧（±170°、180°、0/360）、朝向更新判定（采用 / 冻结 / 保持）。
- 会话：起点门槛（首个达标点、30 秒兜底、无坐标不落位）。
- 地图渲染仍按设计文档 13 手动验证，用 K40 目视箭头朝向与起点落位。
