# 记录页地图北向上，朝向由箭头承担

记录页的实时地图不做 heading-up 旋转：底图始终正北朝上，运动方向由地图上的当前位置箭头旋转表达。旋转整张地图会让瓦片文字与指北徽章一起倒转，而记录页地图本就不可交互、取景由轨迹包围盒驱动，旋转会把「重新取景」和「转向」两种运动叠在一起，让人分不清是自己在拐弯还是相机在转。

## 考虑过的选项

- **heading-up（地图随朝向旋转）**：接近车机导航的习惯，但需要给瓦片文字做反向旋转、把取景逻辑拆成「相机朝向」与「轨迹范围」两套，收益不抵代价。
- **只画圆点、不表达朝向**：改动最小，但用户看不出自己是否走反了方向。

## 影响

指北徽章因此永远指北，可以保留；朝向只在箭头这一处表达，不要再引入第二个转向提示。

## 修订（2026-10-29）

一天后回到北向上。heading-up 在真机上晃得厉害：GPS 朝向逐秒抖，整张图跟着转，看轨迹反而更累；而且用户真正要的是「我在画面正中」，方向交给箭头就够。现行为：

- 地图不旋转，始终北向上，方向只由当前位置箭头（`AnimatedRotation`，200ms 最短弧）表达；
- 相机每一个新点都把当前位置放到屏幕正中，320ms 缓动平移，不再等出安全区才跳；
- 指北徽章停止跟随盘面，恢复固定朝上。

前一次的修订记录保留在下面，作为「heading-up 试过、不采用」的依据。

## 已废弃（2026-10-28）：heading-up

曾改成地图按朝向反向旋转（`rotation = -heading`）、箭头固定朝上、指北徽章跟着盘面转，旋转带 420ms 补间和 3° 死区。实机上车速一提整张图就跟着朝向抖，读轨迹比北向上更累，次日撤回。
